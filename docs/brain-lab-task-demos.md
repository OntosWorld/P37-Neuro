# P37 Brain Lab — interactive experiments and cross-embodiment evidence

## What visitors can actually do

P37 Brain Lab contains ten official MuJoCo Menagerie robot models and three
interactive task scenes assembled from genuine MJCF components:

| Demo | Robot | Real physical interaction | Control source |
|---|---|---|---|
| G1 Impact Lab | Unitree G1 | A movable, weighted sphere can collide with a humanoid | MuJoCo only |
| Go2 Contact Field | Unitree Go2 | Three obstacles of different heights create contact constraints | MuJoCo only |
| Franka Gravity Stack | Franka Panda | Unattached blocks drop, collide and stack under gravity | MuJoCo only |

A visitor selects a scene from **Demos** or the scene strip. Camera interaction,
object dragging, scene reset and model switching run in the browser using
MuJoCo WebAssembly, without a video or pre-scripted successful outcome.

All scenario objects are defined in `sim/web/demo_specs.py`. Additional scenes
are registered in `sim/web/build_mjswan.py` and validated by the same Chromium
and GitHub Pages workflows as the robot gallery.

## Measured P37 cross-embodiment experiment

A separate native experiment exercises **the same frozen checkpoint** on
two materially different genuine robot bodies:

- G1: 29 joint action outputs, 30 executed control steps, 0.6 simulated seconds
- Go2: 12 joint action outputs, 30 executed control steps, 0.6 simulated seconds
- Both outputs were generated by the recurrent P37 model and executed in
  actual native MuJoCo physics.
- No additional fine-tuning or per-body model retraining took place.

Source: [verified GitHub Actions run](https://github.com/OntosRobotics/P37-Neuro/actions/runs/42894652354).
The exact checkpoint digest, action counts and trial measurements are in
`sim/web/cross-body-evidence.json`, copied from that run.

The script is `sim/src/p37_neuro_sim/cross_embodiment_smoke.py`. It loads
the checkpoint created by `g1_p37_train.py`, instantiates the existing
G1/Go2 runtime adapters, passes their own joint tensors through the same
network, and verifies the action shapes and short physics rollouts.

**What it establishes:** the P37 action architecture can use a single
checkpoint with different joint counts, emitting the dimensions needed by
each robot. This is a meaningful interface property compared with a *fixed
joint-count output layer* that directly produces a predetermined number of
actions.

**What it does not establish:** generalized movement, adaptation, learned
walking, task transfer, disturbance recovery, operation on real-world
hardware, or superior performance against other companies' robot brains.
The network was trained on G1, for only one PPO update, and the Go2 test is
only 0.6 seconds. Neither robot has a qualified locomotion policy. The
three embedded browser scenes are physics-only and are **not** controlled
by the P37 model.

## Evidence policy

The website separates two modes:

1. **Live MuJoCo physics:** physically correct contacts and manipulations
   with no trained P37 controller attached.
2. **Verified P37 research:** frozen checkpoint ID and measured native
   model-inference trial results, with direct links to GitHub Actions.

The visitor can switch from the evidence panel into the corresponding
G1 or Go2 interactive scene, but that does **not** turn the browser's
viewer into the trained policy. Do not combine the two modes under an
unqualified `P37-controlled` label.

## Next qualification

To claim the same **learned skill** works on materially different robots,
train a repeatable task-conditioned policy, freeze weights, and execute
held-out closed-loop tasks on at least two body types. Record task success
fraction, falls, distance/pose error, time horizon, energy, recovery,
safety overrides, episode videos, seeds and checkpoint hashes. Compare
against a declared same-compute single-body baseline.

Only publish a competitive claim when a real matched comparison establishes it.
